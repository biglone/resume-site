## 01. 结论先行

**项目定位**：自托管文件上传、分片续传、公开分享和审计管理系统。

这个项目的工程主线可以概括为：**Web产品与数据服务**。面试时应优先讲清业务目标、关键边界、个人负责模块，以及设计如何降低实时性、稳定性、兼容性或交付风险。

### 适合展示的项目信号

- 使用 Go + React + PostgreSQL 构建管理端、API 和对象存储抽象。
- 实现分片上传、会话清理、分享密码、过期时间、下载次数和审计日志。
- 支持本地存储和 S3-compatible 存储，并提供 Docker/Cloudflare Tunnel 部署。

### 公开可核对指标

- **上传能力**：普通 + 分片续传
- **存储后端**：Local / S3-compatible
- **安全控制**：密码 / 过期 / 次数

## 技术难点与我的贡献
- 抽象存储后端，统一本地磁盘和 S3-compatible 对象存储，业务层不依赖具体部署环境。
- 将大文件上传拆成可恢复的分片会话，配合过期清理、配额拦截和校验，减少临时文件残留与重复上传。
- 为分享链接设计密码、过期时间、最大下载次数和审计日志等策略，并用 Go/React/PostgreSQL、Docker 完成可部署闭环。
